# Board Tracker 로컬 + Claude Code 전환 설계

## 의도

Vercel에 배포하던 Board Tracker 웹 앱을 내 PC의 `localhost`에서만 돌리고, 이사 명단 추출(지금은 OpenRouter GPT-4.1)을 **열려 있는 Claude Code 세션이 직접** 하도록 바꾼다. 사용자는 이 앱을 Claude Code 안에서만 실행한다. 방식은 `~/work/virtual_BoD`와 같다. 세션에서 시작하면 Claude가 로컬 서버를 백그라운드로 띄우고, Claude가 LLM 역할을 맡는다.

왜: 외부 LLM API 키와 비용, Vercel/Neon/Blob 같은 클라우드 의존을 없애고, 혼자 쓰는 도구로 단순하게 만든다.

## 사용 흐름 (사용자가 정한 것)

1. Claude Code 세션(이 저장소)에서 "보드트래커 시작"이라고 한다.
2. Claude가 웹 서버를 백그라운드로 띄우고, 요청 감시를 켠 뒤, 브라우저 주소를 알려준다.
3. 사용자가 브라우저에서 지금처럼 회사/연도를 고르고 조회한다.
4. 서버가 로컬 캐시를 확인한다. 있으면 바로 반환한다.
5. 없으면 서버가 지금처럼 DART API에서 사업보고서를 받아 이사회 섹션을 잘라낸 뒤, **요청 파일**로 남긴다.
6. 세션의 Claude가 요청을 알아채고 섹션을 읽어 이사 명단(이름, 직위)을 **결과 파일**로 쓴다. 진행 상황은 터미널에 보인다.
7. 서버가 결과를 받아 캐시에 저장하고 브라우저에 돌려준다.

## 목표

- 화면과 기능은 지금과 같다: 대시보드(회사·연도 선택), 결과 페이지, 관리자 페이지(캐시 조회·선택 삭제·전체 삭제, 회사 추가·삭제).
- DART 수집과 이사회 섹션 추출 로직(`lib/dart.ts`, `lib/parser.ts`)은 그대로 쓴다.
- 이사 명단 추출은 Claude Code 세션이 한다. 외부 LLM API를 호출하지 않는다.
- Claude Code 세션 밖에서 필요한 건 `localhost` 서버와 DART API 키뿐이다.

## 비목표

- 최상위 Python CLI(`main.py`, `src/`, `config.py`)는 손대지 않는다. 여기는 아직 OpenRouter를 쓰지만 이번 범위가 아니다.
- 배포, 다중 사용자, 원격 접속은 고려하지 않는다.
- UI 디자인 개편은 하지 않는다.

## 실패로 보는 것 (기능이 돌아가도)

- 섹션에 없는 이사를 지어내거나, 섹션에 있는 이사를 빠뜨린다.
- Claude 세션이 감시 중이 아닌데 브라우저가 아무 안내 없이 무한 대기한다.
- 시크릿(`.env*`)이 git에 들어간다.

## 결정 사항

### 저장소 구조 (사용자 결정: 합치기)
- 예전 계정의 별도 저장소였던 `board-tracker-web/`을 이 저장소 안의 `web/`으로 옮긴다. 파일만 복사하고 git 이력은 가져오지 않는다. 이력 보존은 필요 없다고 판단했다(Claude 판단).
- 옮긴 뒤 로컬 `board-tracker-web/` 폴더를 지운다. 여기에는 `.git`과, 더는 쓰지 않는 Neon/OpenRouter/Blob/JWT 시크릿이 든 `.env.local*`이 포함된다. 최상위 `.gitignore`의 `/board-tracker-web/` 줄도 정리한다.
- GitHub의 `EddieJung80/board-tracker-web` 저장소는 Claude가 지우지 않는다. 지금 로그인된 계정(`edj-dev-studio`)에는 그 저장소 권한이 없고, 원격 삭제는 되돌릴 수 없다. 필요하면 사용자가 직접 지운다.

### 요청 처리 방식 (사용자 결정: A안, 세션이 처리)
- 서버와 Claude는 **파일 큐**로 주고받는다. 런타임 파일(큐, 하트비트, 캐시 DB, 회사 목록)은 모두 git 대상에서 뺀 `web/.runtime/` 아래에 둔다(Claude 판단).
  - 요청: `web/.runtime/queue/pending/<id>.json`. 회사명, 종목코드, 연도, 이사회 섹션 텍스트를 담는다.
  - 결과: `web/.runtime/queue/done/<id>.json`. `{ "directors": [{ "name", "position" }] }` 또는 `{ "error": "..." }`.
- Claude는 `Monitor` 도구로 `web/.runtime/queue/pending/`을 폴링해 새 요청이 생길 때마다 알림을 받는다. `inotifywait`가 없으니 셸 폴링 루프를 쓴다.
  - Monitor는 최대 30분이면 만료된다. 만료 알림을 받으면 Claude가 다시 켠다.
- **하트비트**: 감시 스크립트가 폴링할 때마다 `web/.runtime/heartbeat`를 갱신한다. 서버는 요청을 넣기 전에 하트비트를 확인한다. 하트비트가 일정 시간(예: 60초) 넘게 멈춰 있으면, 대기하지 않고 바로 오류를 돌려준다. 오류 문구: "Claude Code 세션에서 '보드트래커 시작'을 먼저 실행하세요."
- `/api/analyze`는 캐시에 없으면 요청 파일을 쓰고, 결과 파일이 생길 때까지 서버 쪽에서 기다렸다가 응답한다. 프런트엔드의 순차 호출 구조는 그대로 둔다. 기다리다 시간을 넘기면 오류로 응답한다.
  - 대기 시간 상한과 폴링 간격은 구현자가 정한다(Claude 판단).
  - 결과 파일을 읽은 뒤 요청·결과 파일은 정리한다.

### 추출 규칙 (기존 `lib/llm.ts` 프롬프트를 스킬로 옮김)
- 해당 연도 이사회의 모든 구성원(사내이사, 사외이사, 기타비상무이사, 대표이사 등)을 이름과 직위로 뽑는다.
- 괄호로 나열된 이름(예: `사내이사 3인(이름1, 이름2...)`)을 빠짐없이 확인한다.
- 섹션 텍스트에 있는 정보만 쓴다. 섹션이 비었거나 명단을 찾을 수 없으면 빈 배열과 사유를 쓴다.

### 클라우드 의존 제거 (Claude 판단)
- Neon Postgres 캐시를 로컬 SQLite로 바꾼다. 테이블 구조와 관리자 API 동작은 같게 둔다. 파일은 git 대상에서 뺀다. Node 24 내장 `node:sqlite`를 우선 검토한다.
- Vercel Blob에 있던 회사 목록은 로컬 JSON 파일로 바꾼다. 없으면 `data/companies-seed.json`으로 초기화한다. 관리자 페이지에서 바꾼 목록은 이 파일에 저장하고, git 대상에서는 뺀다.
- 로그인을 없앤다. 대상은 접속 코드 화면, `/api/auth`, `/api/me`, `proxy.ts` 접근 제어, JWT다. 첫 화면은 바로 대시보드로 가고, 관리자 페이지는 바로 열린다.
- 쓰지 않게 된 의존성(`openai`, `@neondatabase/serverless`, `@vercel/blob`, `jose`)과 `.vercel/`을 지운다.
- DART API 키는 `web/.env.local`의 `DART_API_KEY` 하나만 둔다. 값은 최상위 `.env`에 있는 키를 쓴다.

### Claude Code 스킬
- 프로젝트 스킬 `.claude/skills/board-tracker/SKILL.md`를 만든다. 트리거는 "보드트래커 시작", "board tracker 실행" 같은 말이다.
- 스킬이 Claude에게 지시하는 일:
  1. 서버를 `run_in_background`로 띄운다. 의존성이 없으면 먼저 설치한다.
  2. 준비되면 주소를 알려준다.
  3. 큐 감시 Monitor를 켠다.
  4. 요청이 오면 추출 규칙대로 결과 파일을 쓰고, 터미널에 한 줄로 보고한다(예: `SK텔레콤 2024 — 8명`).
  5. Monitor가 만료되면 다시 켠다.
  6. "보드트래커 종료"라고 하면 서버와 감시를 멈춘다.
- 최상위 `CLAUDE.md`에 이 실행 방식과 `web/` 구조를 짧게 적는다.

## 구현자에게 맡기는 것

- Next.js 16은 학습 데이터와 API가 다를 수 있다. `web/AGENTS.md`의 안내대로 `node_modules/next/dist/docs/`를 먼저 확인한다.
- 큐 id 형식, 대기 상한, 폴링 간격, SQLite 파일 위치, 감시 스크립트를 파일로 둘지 인라인으로 둘지.
- 검증: 지금 자동 테스트가 없다. 다음 두 가지는 실제로 돌려서 확인한다.
  - 실제 DART 키로 한 회사·한 연도(예: SK텔레콤 2024)를 처음부터 끝까지 조회한다. 같은 조회를 다시 하면 캐시에서 나와야 한다.
  - 하트비트가 없을 때 안내 오류가 나와야 한다.
- 순수 로직(큐 읽기·쓰기, 하트비트 판정, 캐시)에 단위 테스트를 붙일지.
- README의 Vercel 관련 내용을 로컬 실행 방법으로 바꾼다.
